# pd: меню окон PolyDaemon

Запускает окна агентов (Claude Code, Codex, OpenCode, MiMo) в папках `~/Work`
и подключает к уже запущенным tmux-сессиям. Новые папки и сессии находит сам,
ничего не кэширует.

```
~/Work/pd                       меню (dialog → whiptail → обычный select)
~/Work/pd ls                    запущенные окна
~/Work/pd ws                    найденные папки и их агенты
~/Work/pd attach SAN codex      подключиться (агент по умолчанию: claude)
~/Work/pd start SAN codex new   запустить в фоне и подключиться; без new продолжает последнюю сессию
```

Отключиться от окна, не закрывая его: `Ctrl-b d`. Внутри tmux меню делает
`switch-client`, а не вложенный attach.

## Как находит

- **Папки**: всё, что лежит в `PD_WORK_DIR` не глубже `PD_DEPTH` уровней и
  содержит лаунчер какого-нибудь агента (`polydaemon-<agent>.sh`, старые `tg-*.sh`).
  `node_modules`, `.git`, `tmp`, `local` и подобные пропускаются (`PD_PRUNE`).
- **Сессии**: все tmux-сессии. Агент определяется по префиксу имени
  (`pd-codex-…` → Codex, `pd-opencode-…`, `pd-mimo-…`, остальные `pd-…` → Claude),
  папка определяется по стартовому каталогу сессии. Сессии без префикса
  показываются как `tmux`.
- **Статус**: `●` подключено, `○` в фоне, `⚠` агент вышел и в панели остался
  shell. «Активность» — время последнего вывода в окне.

## Запуск окна

Меню само создаёт tmux-сессию (`pd-<папка>` для Claude, как это делает
`polydaemon-claude.sh`; `pd-codex-<папка>` и т. д. для остальных) и запускает в ней
лаунчер папки. Окружение передаётся так же, как в `polydaemon-claude.sh`: файл
`export -p` с правами 0600, удаляется сразу после чтения. `TMUX`/`TMUX_PANE` в него
не попадают. Codex внутри tmux сам открывает сайдбар PolyDaemon.

- «Продолжить» при уже запущенном окне просто подключает к нему: второй клиент
  на тот же тред не нужен. Из меню второй всё же можно открыть, оно предупредит.
- «Новая» всегда открывает отдельную сессию (`pd-SAN-2`, …).
- Если лаунчер упал в первые `PD_START_CHECK_SEC` секунд, меню покажет его
  последние строки и уберёт мёртвую сессию.

## Устройство

```
pd                 точка входа: меню и команды
lib/core.sh        настройки, помощники, реестр агентов
lib/ui.sh          диалоги: dialog / whiptail / plain, один интерфейс
lib/workspaces.sh  поиск папок
lib/sessions.sh    tmux: список, запуск, подключение, остановка
agents/*.sh        по файлу на агента
theme/dialogrc     тёмная тема dialog (если нет своего ~/.dialogrc)
tests/smoke.sh     тест на отдельном tmux-сервере с заглушками, живые окна не трогает
```

**Новый агент** — один файл в `agents/`:

```bash
# agents/50-foo.sh
pd_agent_register foo 'Foo' 'pd-foo-' polydaemon-foo.sh
# по желанию:
pd_agent_foo_session() { printf 'pd-foo-%s' "$(pd_sanitize "$(basename "$1")")"; }
pd_agent_foo_args()    { [ "$1" = new ] && printf 'new'; }
```

**Новый бэкенд меню** — ещё одна ветка `case` в `ui_menu`, `ui_yesno`, `ui_msg`,
`ui_info` в `lib/ui.sh`.

## Настройки

Переменные окружения или файл `~/.config/pd-menu/config` (обычный bash):

| Переменная | По умолчанию | Что |
|---|---|---|
| `PD_WORK_DIR` | `~/Work` | где искать папки |
| `PD_DEPTH` | `2` | на сколько уровней вглубь |
| `PD_UI` | `auto` | `dialog`, `whiptail` или `plain` |
| `PD_START_CHECK_SEC` | `3` | сколько окно должно прожить, чтобы считаться запущенным |
| `PD_PRUNE` | `node_modules .git tmp local …` | какие каталоги не обходить |
| `PD_TMUX_SOCKET` | пусто | `tmux -L <имя>`, нужно для тестов |

Требования: bash 4+, tmux, dialog или whiptail (без них работает простой
текстовый режим). Проверка: `tests/smoke.sh`, `shellcheck -x pd lib/*.sh agents/*.sh`.
